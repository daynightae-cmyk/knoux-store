# Trusted WordPress operations

The existing directory and domain search remain read-only. Domain registration returns `REGISTRATION_REQUIRES_OPERATOR`; this application has no purchase adapter and makes no registration or billing call.

WordPress operations use a separately operated, trusted HTTPS executor. Configure server environment names `KNOUX_WORDPRESS_EXECUTOR_URL`, `KNOUX_WORDPRESS_EXECUTOR_TOKEN`, and comma-separated `KNOUX_WORDPRESS_SITE_IDS`. The application requires an authenticated Build operator, same-origin requests, a site allowlist, a closed action vocabulary, and explicit confirmation for mutations. Credentials remain server-side. Without configuration the console reports `NOT_CONFIGURED`; configuration alone does not establish connectivity.

The adapter posts to `v1/wordpress/operations` beneath the configured base URL, with bearer authorization and an `idempotency-key` equal to the request UUID. The body contains `ownerId`, `requestId`, `siteId`, `action`, and validated optional `slug`, `reference`, `activate`, and `confirmation` fields. A remote executor must independently authorize the owner and site, atomically deduplicate the UUID, bind it to an identical operation payload, and retain a durable receipt before dispatching work. Never interpret browser values as shell commands. Map approved site IDs to server-managed installation paths; use argument arrays for controlled WP-CLI invocations. Restore, migration, and deployment references identify previously reviewed executor artifacts, never browser paths or URLs.

The response must echo `requestId`, `siteId`, and `action`, and return an explicit `READY`, `RUNNING`, `SUCCEEDED`, `FAILED`, or `BLOCKED` state. `RUNNING` and `SUCCEEDED` require a durable `externalReference`. Optional `version` and `items` (slug, version, active) are normalized; remote logs and arbitrary error text are withheld. HTTP 200 alone cannot establish success. A transport timeout reports `EXECUTOR_NOT_CONNECTED` and retains the UUID: reconcile the remote receipt before retrying any mutation with a new UUID.

Backups, verified restore points, least-privilege execution, and production approval policies belong to the trusted executor. The application does not claim those controls are connected or verified until an actual configured executor reports evidence. Automated tests use isolated contract fixtures and never purchase domains or mutate a WordPress site.
