## 5. Key Security Patterns

| Pattern | Implementation |
|---------|----------------|
| **RLS everywhere** | Every business table has RLS + policies |
| **Anon revoked** | `revoke all on table ... from anon` on all Growth/Provider/Bridge/Signal tables |
| **Service role only** | Admin RPCs, vault access, enrollment, job claim — `security definer` + `revoke from public,anon,authenticated; grant to service_role` |
| **Vault for secrets** | `knoux_growth_private.secret_owners` maps vault secrets to owners; `knoux_provider_credentials.encrypted_value` uses AES-256-GCM |
| **SHA-256 token hashes** | All bearer tokens stored as SHA-256 hashes only |
| **OAuth state binding** | `state_hash` + `binding_hash` + owner verification |
| **Plan hash binding** | Campaign approvals bind to `plan_hash`; edits invalidate approval |
| **No self-approval** | `knoux_growth_campaign_approvals_not_self_approved` constraint |
